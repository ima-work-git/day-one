# 要件定義書 — Day One

## プロジェクト概要

**サービス名**: Day One

**コアコンセプト**:
- **Day One**：初心・原点・最も強い動機を持っていた瞬間
- **Day Two**：初心を忘れ、モチベーションが落ちた状態
- **価値提案**：過去の自分（Day One）の声・記録を使って、今の自分（Day Two）を原点に引き戻す

Day Twoのあなたをダメにする（＝Day Oneに戻す）という逆説的なコンセプトは、AWSの「Day 1精神（常に創業初日の姿勢で）」とも深く共鳴する。

---

## ターゲット・ビジネスモデル

### 初期ターゲット（MVP）
**BtoB — 企業研修部門・研修会社**
- 入社時・研修時に「Day Oneの自分」を記録
- 数年後に振り返りの機会を設ける
- エンゲージメント向上・キャリア自立支援

**設計方針**: アカウントタイプ（BtoB/BtoC）に関わらず、すべてのユーザーが個人としてDay Oneを記録・対話できる。BtoBは管理機能が追加されるだけで、コア体験は共通。

### 将来ターゲット（拡張）
- 婚活会社・結婚式場（誓いの気持ちを保存）
- 刑務所・更生施設（出所時の決意を記録）
- 個人起業家・フリーランス（モチベーション維持）
- スポーツ選手（悔しさ・決意の保存）
- ダイエット・健康管理（目標体重・理想の自分を記録し、挫折しそうなときに原点回帰）
- 高校・塾・大学（大学受験・進路決定時の決意を記録。高校生には学生アカウントとして無料配布、大学は機関契約で学生に提供）
- 家具メーカー・スマートデバイスメーカー（ハードウェア連携）

### マネタイズモデル
- **BtoB**: 月額・年額サブスクリプション（企業単位）
- **BtoC**: 月額・年額サブスクリプション（個人単位）
- **教育機関向け**: 高校・塾は機関契約、高校生には学生アカウントを無料配布。大学は機関契約で在学生に提供
- 将来的にフリーミアムも検討

## 機能要件

### FR-01: Day One記録機能（カスタマイズ可能なガイド付きフォーマット）
- **概要**: ユーザーが「Day Oneの自分」の情報を、ガイド付きフォーマットに沿ってテキストで入力・保存する
- **デフォルトフォーマット（用途別）**:
  - **汎用（標準）**: 今この瞬間の気持ち・感情 / この決断・スタートをした理由・動機 / やりたいこと・夢・目標 / なりたい人物像・なりたくない人物像 / 未来の自分へのメッセージ / 今の自分を象徴する一言
  - **企業研修用**: 入社を決めた理由 / やりたいこと・目標 / なりたい社会人像・なりたくない社会人像 / 3年後の自分へのメッセージ
  - **スポーツ用**: 悔しさ・今の感情 / 決意・誓い / 目標
  - **受験・進路用**: この大学・学部を目指す理由 / 合格したら何をしたいか / なりたい自分・なりたくない自分
  - **ダイエット・健康用**: なぜ始めるか / 理想の自分の姿 / なりたい自分・なりたくない自分 / 未来の自分へのメッセージ
- **フォーマットのカスタマイズ**:
  - **個人アカウント（BtoC）— 自由型**: デフォルトはあくまで出発点。全項目の文言編集・削除・並び替えが自由。独自項目を最大5項目まで追加可能（LLM・TTS処理コストのため上限あり）。利用者本人が自分のために自由に使うことを前提とする
  - **企業アカウント（BtoB）— 制約型**: 管理者の意図を守るための制約型。管理者が設定した必須項目はユーザーが変更・削除不可（ロック）。ユーザーは独自項目を最大3項目まで追加可能（管理者が上限を変更可能）
  - **BtoB管理者**: 組織用フォーマットを作成し、項目ごとに「必須/任意」を設定して従業員に配布可能（フェーズ2で実装）
- **フォーマットの目的**: 記録時に「Day Oneの気持ち」を漏らすことなく引き出し、後の対話AIが豊かな文脈で応答できるようにする
- **記録タイミング**:
  - 自由記録：ユーザーが任意のタイミングで記録
  - イベント記録：BtoB管理者が設定した特定イベント時（入社日など）に記録を促す通知を送信
- **優先度**: Must Have

### FR-01b: クローンボイス用テキスト読み上げ収録機能
- **概要**: テキストフォーマット入力完了後、入力した文章をすべて声に出して読み上げる収録ステップを設ける
- **フロー**:
  1. テキスト入力完了 → 「次へ：声を録音する」ボタン
  2. 入力したテキストが画面に表示され、ユーザーがそれを読み上げながら録音
  3. 録音完了 → クローンボイス生成へ
- **目的**: テキストと音声の内容を一致させることで、クローンボイスが「Day Oneの文脈」を正確に再現できるようにする。また、自分の言葉を声に出すことで記録の実感・コミットメントを高める
- **優先度**: Must Have

### FR-02: クローンボイス生成機能
- **概要**: 収録した音声データをもとに、ユーザーのクローンボイスモデルを生成する
- **技術方針**: ElevenLabs Voice Cloning API を使用。日本語対応・クローンボイス生成に対応した低レイテンシ TTS
- **レイテンシ要件**: 対話のリアルタイム性が重要なため、低レイテンシモデルを優先選定する。音声合成の応答開始まで 2〜3 秒以内（NFR-01 参照）
- **生成タイミング**: 音声収録完了後、バックグラウンドで非同期処理
- **優先度**: Must Have（MVP中核機能）

### FR-03: クローンボイス双方向対話機能
- **概要**: 生成したクローンボイスを使い、過去の自分とリアルタイムで双方向AI対話を行う
- **仕組み**:
  1. ユーザーがホーム画面で話しかけたい「Day Oneの自分」を選択（例：「入社初日の自分」「ダイエットを決意した自分」「薬物との決別を決意した日の自分」）
  2. ユーザーが発話（またはテキスト入力）
  3. LLM（Amazon Bedrock Nova 2 Lite）が「Day Oneの自分」として、記録フォーマットの内容を文脈に応答を生成
  4. クローンボイスで音声合成して返答
- **対話後メモ**: セッション終了後に振り返りメモ（自由記述）を保存できる。BtoB研修での「今の自分との比較」も個人の「今日も踏みとどまれた」記録も、同一の振り返りメモ機能で統一する
- **対話開始タイミング**:
  - システムからのリマインド通知経由
  - ユーザーが任意のタイミングで自発的に開始（いつでも対話可能）
- **優先度**: Must Have（MVP中核機能）

### FR-04: 定期リマインド・再生機能
- **概要**: 設定したスケジュールで「Day Oneの記録」を通知し、対話セッションへ誘導する
- **通知チャネル**: Webプッシュ通知、メール
- **スケジュール設定**: ユーザー自身が設定（毎週・毎月・特定日など）、BtoB管理者も設定可能
- **優先度**: Should Have

### FR-05: ユーザー認証・アカウント管理
- **概要**: ユーザー登録・ログイン・プロフィール管理
- **認証方式**: メール＋パスワード、ソーシャルログイン（Google）
- **BtoBアカウント連携**: 企業管理者が発行した招待リンク経由でのアカウント作成に対応
- **優先度**: Must Have

### FR-06: メディアストレージ管理
- **概要**: テキスト・音声・画像・動画をクラウドに保存・管理する
- **ストレージ**: AWS S3
- **優先度**: Must Have

### FR-07: BtoB管理機能（フェーズ2）
- **概要**: 企業管理者が従業員の記録状況・リマインド設定・招待管理を行うダッシュボード
- **優先度**: Won't Have（フェーズ2で実装）

## 非機能要件

### NFR-01: パフォーマンス
- クローンボイス生成：初回生成は30秒以内（非同期処理）
- 対話応答：2〜3秒以内（LLM応答＋音声合成の合計）
- ページロード：3秒以内（LCP）

### NFR-02: スケーラビリティ
- 初期：同時接続100ユーザー対応
- 将来：BtoB展開に向けてマルチテナント対応可能な設計

### NFR-03: データプライバシー・セキュリティ
- ユーザーの音声・動画データは個人情報として厳重に管理
- HTTPS通信の徹底
- AWS S3 のサーバーサイド暗号化（SSE）を適用
- 将来的にエンドツーエンド暗号化（E2E）へ移行可能な設計

### NFR-04: 可用性
- 目標稼働率：99%以上

### NFR-05: ユーザビリティ
- 初回記録完了まで5分以内で完了できるUX
- ガイド付きフォーマットにより、記録の抜け漏れを防ぐ
- 日本語UI（初期リリース）

### NFR-06: テスト方針
- 基本的な単体テスト・統合テストを実施

## ユーザーシナリオ（主要）

### シナリオ1: 企業研修での初回記録〜対話（BtoB）

**前提**: 企業がDay Oneを導入済み。管理者アカウントが存在する。

1. **企業管理者の初期設定**
   - 管理者がDay OneのBtoBプランに登録し、企業アカウントを作成
   - 「入社日」をイベントトリガーとして設定
   - 新入社員のメールアドレスを登録し、招待リンクを一括送信

2. **新入社員のアカウント作成**
   - 新入社員が招待メールのリンクをクリック
   - 氏名・パスワードを設定するだけでアカウント作成完了（メールアドレスは招待時に設定済み）
   - 企業アカウントに自動紐付け

3. **Day One記録（入社初日）**
   - ログイン後、「Day Oneを記録しよう」の画面が表示される
   - ガイド付きフォーマットに沿ってテキストを入力：
     - 「入社を決めた理由・動機」
     - 「やりたいこと・夢・目標」
     - 「なりたい人物像・なりたくない人物像」
     - 「3年後の自分へのメッセージ」
     - 「今の自分を象徴する一言」
   - テキスト入力完了後、「次へ：声を録音する」ステップへ
   - 入力したテキストが画面に表示され、ユーザーがそれを読み上げながら録音（1〜3分程度）
   - 写真（任意）をアップロード
   - 「記録する」ボタンで保存
   - バックグラウンドでクローンボイス生成が開始される（完了時に通知）

4. **定期リマインド（入社2年後）**
   - システムが設定スケジュールに従い、メール＋プッシュ通知を送信
   - 「2年前のあなたが話しかけています」という通知文言

5. **クローンボイス対話（リマインド経由）**
   - 通知をタップしてアプリを開く
   - 「Day Oneの自分」との対話セッションが開始
   - 過去の自分の声（クローンボイス）で「入社を決めた理由」「3年後の自分へのメッセージ」を語りかけてくる
   - ユーザーが発話・返答することで双方向対話が進む
   - セッション終了後、振り返りメモを保存できる

6. **任意タイミングでの対話**
   - リマインド通知を待たずに、ユーザーがいつでもホーム画面から「Day Oneの自分と話す」ボタンで対話セッションを開始できる
   - 仕事で行き詰まったとき・転職を考えたときなど、自発的に原点回帰できる

---

### シナリオ2: ダイエット・健康管理（BtoC）

**前提**: 個人ユーザーが自分でアカウント登録して利用。

1. ユーザーがWebアプリにアクセスし、メールアドレスでアカウント登録
2. ダイエット開始日に「Day One」をダイエット用フォーマットで記録
   - 「なぜ痩せたいのか」「理想の自分の姿」「なりたい自分・なりたくない自分」「1年後の自分へのメッセージ」
   - 現在の写真（任意）
   - テキスト入力後、読み上げ録音 → クローンボイス生成（バックグラウンド）
3. 毎週月曜日にリマインド通知を設定
4. 挫折しそうなとき・食欲に負けそうなときにホーム画面から「Day Oneの自分と話す」を選択
5. 過去の自分の声（クローンボイス）で「なぜ始めたか」「なりたい自分・なりたくない自分」を語りかけられ、継続意欲を取り戻す
6. セッション終了後、振り返りメモを保存

---

### シナリオ3: 大学受験・進路決定（教育機関）

**高校・塾での活用**:
1. 高校または塾がDay Oneと機関契約
2. 高校生に学生アカウントを無料配布（招待リンク経由）
3. 受験勉強開始時・志望校決定時に「Day One」を記録
   - 「この大学・学部を目指す理由」
   - 「合格したら何をしたいか」
   - 「なりたい自分・なりたくない自分（勉強をサボった自分）」
4. 受験期間中、モチベーションが落ちたときに「Day Oneの自分と話す」
5. 過去の自分の声で「なぜ受験を決めたか」を語りかけられ、踏ん張れる

**大学での活用**:
1. 大学がDay Oneと機関契約
2. 入学式・ガイダンス時に在学生全員にアカウントを配布
3. 入学時の「なぜこの大学・学部を選んだか」「4年間で何を成し遂げたいか」を記録
4. 就活・卒論・スランプ時に原点回帰

## 技術スタック・アーキテクチャ

### プラットフォーム
- **MVP**: Webアプリケーション（レスポンシブ対応）
- **将来**: スマートフォンアプリ（iOS/Android）、スマートデバイス連携

### クラウドインフラ
- **クラウドプロバイダー**: AWS
- **ストレージ**: Amazon S3
- **認証**: Amazon Cognito
- **AI/ML**: Amazon Bedrock Nova 2 Lite（LLM）+ Amazon Transcribe（STT）+ ElevenLabs Flash v2.5（クローンボイスTTS・日本語対応・75ms低レイテンシ）

### アーキテクチャ方針
- フロントエンド：Next.js（App Router）/ AWS Amplify
- バックエンド：サーバーレス（AWS Lambda + API Gateway）
- AI処理：Transcribe（STT）→ Nova 2 Lite（LLM）→ ElevenLabs Flash v2.5（TTS）の3段パイプライン
- クローンボイス生成はバックグラウンドジョブ（非同期処理）
