# 要件定義書 — Day 1

## プロジェクト概要

**サービス名**: Day 1

**コアコンセプト**:
- **Day 1**：初心・原点・最も強い動機を持っていた瞬間
- **Day 2**：初心を忘れ、モチベーションが落ちた状態
- **価値提案**：過去の自分（Day 1）の声・記録で、今の自分（Day 2）と**双方向に対話**し、原点に引き戻す

Day 2 のあなたをダメにする（＝ Day 1 に戻す）という逆説的なコンセプトは、AWS の「Day 1 精神（常に創業初日の姿勢で）」とも深く共鳴する。

---

## Day 1 の差別化ポイント（審査向けキーバリュー）

Day 1 は「AI が励ます」サービスではなく、**「過去の自分の声と、今の自分が双方向に対話する」** サービスである。

| 競合 | できること | Day 1 との違い |
|---|---|---|
| ChatGPT 等の汎用 AI チャット | 一般的な励ましアドバイス | 本人の過去データを引用しない／本人の声で返ってこない |
| ジャーナリングアプリ | テキスト記録の振り返り | 一方的に読み返すだけで、過去の自分が答えてくれない |
| AI コーチング | プロのアドバイス模倣 | 「他者の言葉」であり、自分の Day 1 の言葉ではない |
| 音声日記・思い出再生サービス | 録音した音声の再生 | 一方通行の再生のみで、双方向対話がない |

**Day 1 の独自性は次の 4 要素の組み合わせで生まれる**：

1. **本人の過去データ**：Day 1 に入力した動機・目標・なりたい自分が応答の文脈になる
2. **本人の声**：クローンボイスで、過去の自分の声が再生される
3. **双方向対話**：再生して終わりではなく、今の自分が話しかけると過去の自分が答え、対話が往復する
4. **節目通知 × 振り返り**：「2 年前のあなたが話しかけています」で対話を始め、終了後に今の自分を記録する

この 4 つが揃って初めて「過去の自分が、今の自分に応えてくれる」体験が成立する。1 つでも欠けると、よくある AI チャット・音声日記・コーチングアプリに戻ってしまう。

## ターゲット・ビジネスモデル

### 初期ターゲット（MVP）

**BtoB — 企業研修部門・研修会社**
- 入社時・研修時に「Day 1 の自分」を記録
- 数年後に振り返りの機会を設ける
- エンゲージメント向上・キャリア自立支援

**MVP 実装境界**: MVP は BtoB 研修文脈でデモするが、実装対象は従業員本人のコア体験（記録 → 音声収録 → クローンボイス生成 → 対話 → 振り返りメモ）に絞る。企業管理者向けダッシュボード、組織テンプレート編集、一括招待、自動リマインド配信はフェーズ 2 で実装する。

**MVP 運用方針**: 研修用テンプレート、参加リンク、リマインドタイミングは運営者が手動で準備する。したがって、BtoB MVP の画面・API は個人単位の利用体験と共通であり、BtoC への横展開も同じコア実装で成立する。

### 将来ターゲット（拡張）

- 婚活会社・結婚式場（誓いの気持ちを保存）
- 刑務所・更生施設（出所時の決意を記録）
- 個人起業家・フリーランス（モチベーション維持）
- スポーツ選手（悔しさ・決意の保存）
- ダイエット・健康管理（目標体重・理想の自分を記録し、挫折しそうなときに原点回帰）
- 学校・塾・大学（受験・進路決定時の決意を記録。未成年利用時は保護者同意・外部 API 規約確認を前提にする）
- 家具メーカー・スマートデバイスメーカー（ハードウェア連携）

### マネタイズモデル

- **BtoB**: 月額・年額サブスクリプション（企業単位）
- **BtoC**: 月額・年額サブスクリプション（個人単位）
- **教育機関向け**: 学校・塾・大学との機関契約。未成年向け提供は保護者同意・外部 API 規約確認を前提にする
- 将来的にフリーミアムも検討

## 機能要件

### FR-01: Day 1 記録機能（カスタマイズ可能なガイド付きフォーマット）

- **概要**: ユーザーが「Day 1 の自分」の情報を、ガイド付きフォーマットに沿ってテキストで入力・保存する
- **デフォルトフォーマット（用途別）**:
  - **汎用（標準）**: 今この瞬間の気持ち・感情 / この決断・スタートをした理由・動機 / やりたいこと・夢・目標 / なりたい人物像・なりたくない人物像 / 未来の自分へのメッセージ / 今の自分を象徴する一言
  - **企業研修用**: 入社を決めた理由 / やりたいこと・目標 / なりたい社会人像・なりたくない社会人像 / 3 年後の自分へのメッセージ
  - **スポーツ用**: 悔しさ・今の感情 / 決意・誓い / 目標
  - **受験・進路用**: この大学・学部を目指す理由 / 合格したら何をしたいか / なりたい自分・なりたくない自分
  - **ダイエット・健康用**: なぜ始めるか / 理想の自分の姿 / なりたい自分・なりたくない自分 / 未来の自分へのメッセージ
- **フォーマットのカスタマイズ**:
  - **個人アカウント（BtoC）— 自由型**: デフォルトはあくまで出発点。全項目の文言編集・削除・並び替えが自由。独自項目を最大 5 項目まで追加可能（LLM・TTS 処理コストのため上限あり）
  - **BtoB MVP — 研修用固定テンプレート**: 運営者が事前に用意した企業研修用デフォルトフォーマットを使用する。従業員は必須項目に回答し、独自項目を最大 3 項目まで追加できる
  - **BtoB フェーズ 2 — 管理者制約型**: 企業管理者が組織用フォーマットを作成し、項目ごとに「必須 / 任意」を設定して従業員に配布する。必須項目は従業員が変更・削除できない
- **フォーマットの目的**: 記録時に「Day 1 の気持ち」を漏らすことなく引き出し、後の対話 AI が豊かな文脈で応答できるようにする
- **記録タイミング**:
  - 自由記録：ユーザーが任意のタイミングで記録
  - イベント記録：MVP では運営者が研修内で記録を案内する。フェーズ 2 では BtoB 管理者が入社日などのイベントに応じて自動通知を設定する
- **優先度**: Must Have

### FR-01b: クローンボイス用音声収録機能

- **概要**: テキスト入力の後、自分の声で「Day 1 の気持ち」を録音する。ここで録音した音声サンプルからクローンボイスが生成され、後の対話で過去の自分の声として使われる
- **フロー**:
  1. テキスト入力完了 → 「次へ：声を録音する」ボタン
  2. 録音画面で、自分の声で 30 秒〜2 分録音（直前に入力したテキストは参考として画面に表示される）
  3. 録音完了 → クローンボイス生成へ
- **録音時間要件**: 最低 30 秒以上で次へ進める。推奨 1〜2 分（ElevenLabs Instant Voice Cloning の仕様）
- **録音中の支援**: 参考テキスト表示／音量メーター／ノイズ警告
- **目的**: 後の双方向対話で「過去の自分の声」として使えるクローンボイス音声サンプルを収録する
- **優先度**: Must Have

### FR-02: クローンボイス生成機能

- **概要**: 収録した音声データをもとに、ユーザーのクローンボイスモデルを生成する
- **技術方針**: ElevenLabs Voice Cloning API（Flash v2.5、75ms、日本語対応）
- **レイテンシ要件**: 対話応答開始まで 2〜3 秒以内（NFR-01 参照）
- **生成タイミング**: 音声収録完了後、バックグラウンドで非同期処理
- **同意要件**: 録音前に「自分の声でクローンボイスを生成し、第三者 API（ElevenLabs）に送信する」ことへの同意取得が必須（FR-09 参照）
- **優先度**: Must Have（MVP 中核機能）

### FR-03: クローンボイス双方向対話機能（コアバリュー）

- **概要**: 生成したクローンボイスを使い、**過去の自分と今の自分がリアルタイムで双方向対話する**。一方通行の再生ではなく、ユーザーが話しかけると過去の自分が答え、対話が往復する
- **対話のイメージ**:
  > 今の自分（ユーザー発話）：「最近、転職を考えてる」
  > 過去の自分（クローンボイス）：「入社のとき、〇〇をやりたいって書いてたよね。今その仕事には触れられてる？」
  > 今の自分：「正直、最近は雑務ばかりで……」
  > 過去の自分：「じゃあ、〇〇に近づくために今できる小さな一歩は何だろう？」
- **仕組み**:
  1. ユーザーがホーム画面で話しかけたい「Day 1 の自分」を選択（例：「入社初日の自分」「ダイエットを決意した自分」）
  2. ユーザーが発話（またはテキスト入力）
  3. LLM（Amazon Bedrock Nova 2 Lite）が「Day 1 の自分」として、記録フォーマットの内容を System Prompt の文脈に応答を生成
  4. クローンボイスで音声合成して返答
  5. ユーザーがさらに返答 → 過去の自分が応える、という往復が続く
- **対話後メモ**: セッション終了後に振り返りメモ（自由記述）を保存できる。BtoB 研修での「今の自分との比較」も個人の「今日も踏みとどまれた」記録も、同一の振り返りメモ機能で統一する
- **対話開始タイミング**:
  - MVP では運営者が共有する研修用リンク、または簡易メール通知経由
  - ユーザーが任意のタイミングで自発的に開始（いつでも対話可能）
- **優先度**: Must Have（MVP 中核機能・本サービス最大の差別化ポイント）

### FR-04: 定期リマインド・再生機能

- **概要**: 設定したスケジュールで「Day 1 の記録」を通知し、対話セッションへ誘導する
- **通知チャネル**: MVP はメール・研修用リンク。Web プッシュ通知はフェーズ 2
- **MVP**: ユーザー自身の簡易リマインド、または運営者が手動で共有する研修用リンク・メールで対話セッションへ誘導する
- **フェーズ 2**: BtoB 管理者が「入社 X 年後」「研修日」などの一括自動リマインドを設定可能にする
- **優先度**: Should Have

### FR-05: ユーザー認証・アカウント管理

- **概要**: ユーザー登録・ログイン・プロフィール管理
- **認証方式**: メール＋パスワード、ソーシャルログイン（Google）
- **MVP**: 研修参加者は通常登録、デモアカウント、または運営者が共有する参加リンクから利用する
- **フェーズ 2**: 企業管理者が発行した招待リンク経由でのアカウント作成と企業紐付けに対応
- **優先度**: Must Have

### FR-06: メディアストレージ管理

- **概要**: テキスト・音声・画像・動画をクラウドに保存・管理する
- **ストレージ**: AWS S3（SSE-S3 暗号化）
- **優先度**: Must Have

### FR-07: BtoB 管理機能（フェーズ 2）

- **概要**: 企業管理者が組織テンプレート、従業員招待、記録状況、リマインド設定を管理するダッシュボード
- **MVP での扱い**: 企業研修シナリオは運営者の手動準備で代替し、従業員本人のコア体験検証を優先する
- **優先度**: Won't Have（フェーズ 2 で実装）

### FR-08: 会話記憶・継続対話機能（フェーズ 2）

- **概要**: 前回の対話セッションの内容を構造化して記憶し、次回の対話の冒頭に活用する
- **仕組み**:
  1. 対話セッション終了後、LLM が会話内容を自動分析・構造化（話題・感情状態・気づき・次回への問い）
  2. 次回の対話開始時、直近の会話サマリを System Prompt に注入
  3. クローンボイスが「前回、〇〇について話していましたね。その後どうですか？」と自然に問いかける
- **効果**: 単発の対話から「継続的な関係性を持つ過去の自分」へと進化する
- **優先度**: Won't Have（フェーズ 2 で実装）

### FR-09: プライバシー・同意・データ削除

クローンボイス・音声データは個人情報のなかでも特に機微な情報のため、本人同意・削除・第三者送信の透明性を厳格に保証する。

- **録音前の同意取得（必須）**:
  - 自分の声でクローンボイスを生成することへの同意
  - 音声データを第三者 API（ElevenLabs）に送信することへの同意
  - 本人以外の声を登録しないことへの同意（cloning consent）
  - 同意なしでは録音・クローンボイス生成は実行不可（UI でブロック）

- **データ削除権**:
  - ユーザーは録音音声・クローンボイス（ElevenLabs Voice ID）・対話履歴・振り返りメモをいつでも個別に削除できる
  - 退会時は関連データすべて（DynamoDB / S3 / ElevenLabs Voice ID）を削除する
  - 削除リクエストから 30 日以内に物理削除完了

- **第三者 API 送信の開示**:
  - 利用規約・プライバシーポリシーで「クローンボイス生成・音声合成のために ElevenLabs に音声データを送信する」ことを明示
  - ElevenLabs の利用規約上、入力コンテンツ・ユーザーボイスモデルに関するライセンス、サービス改善・モデル改善への利用可能性、データ利用オプトアウトの扱いを確認し、ユーザーに開示する

- **悪用防止**:
  - 同一アカウントで複数のクローンボイスを登録する際も、毎回同意を取得
  - 将来拡張：本人確認のため録音時に決まったフレーズ（パスフレーズ）の発話を含める／顔写真と音声の同時登録

- **法的考慮**:
  - 米国 12 州以上に音声クローン関連法あり（カリフォルニア、NY、テネシー ELVIS Act 等）
  - 日本でも肖像権・パブリシティ権・個人情報保護法（音声＝個人識別符号）への配慮
  - GDPR / CCPA を見据え、ユーザーが自身のデータをエクスポート・削除できる仕組みを設計時から組み込む

- **優先度**: Must Have（MVP で実装）

## 非機能要件

### NFR-01: パフォーマンス（測定方法・達成条件付き）

| 指標 | 目標値 | 測定方法 | 達成条件 |
|---|---|---|---|
| AI 応答開始（テキストのみ） | 通常時 3 秒以内 | CloudWatch Metrics（Lambda Duration p95） | デモ環境で 80% のリクエストが 3 秒以内 |
| AI 応答開始（音声合成込み） | 5 秒以内 | WebSocket イベント時刻のクライアント計測 | デモ環境で 80% のリクエストが 5 秒以内 |
| クローンボイス初回生成（非同期） | 30 秒以内 | EventBridge イベント時刻 | 90% のジョブが 30 秒以内に完了 |
| ページロード（LCP） | 3 秒以内 | Web Vitals（Real User Monitoring） | 75 パーセンタイルで 3 秒以内 |

### NFR-02: スケーラビリティ

- **MVP デモ目標**: 同時接続 10 ユーザーで動作確認（ハッカソン期間中の負荷想定）
- **プロダクション目標**: 同時接続 100 ユーザー（要負荷試験、フェーズ 2）
- **将来**: BtoB 展開に向けてマルチテナント対応可能な設計
- **検証方法**: Locust または k6 によるロードテスト（フェーズ 2 で実施）。MVP では複数ブラウザでの同時操作確認のみ

### NFR-03: データプライバシー・セキュリティ

- HTTPS 通信の徹底（TLS 1.2 以上）
- AWS S3 サーバーサイド暗号化（SSE-S3）
- DynamoDB 保存時暗号化（AWS 管理 KMS キー）
- Cognito JWT による認証・認可
- IAM 最小権限の原則（Lambda 実行ロールはサービス毎に分離）
- 詳細は FR-09 を参照
- 将来：エンドツーエンド暗号化（E2E）への移行可能設計

### NFR-04: 可用性

- **MVP デモ目標**: ハッカソン期間中・審査デモ時間帯の連続稼働
- **プロダクション目標**: 月間稼働率 99% 以上（SLA 設定はフェーズ 2）
- **検証方法**: CloudWatch Synthetics による定期ヘルスチェック（フェーズ 2）。MVP では手動疎通確認

### NFR-05: ユーザビリティ

- 初回記録完了まで 5 分以内で完了できる UX
- ガイド付きフォーマットにより、記録の抜け漏れを防ぐ
- 日本語 UI（初期リリース）
- アクセシビリティ：WCAG 2.1 AA を将来目標（MVP は基本的なキーボード操作・スクリーンリーダー対応のみ）

### NFR-06: 観測性・テスト方針

- CloudWatch Logs によるログ収集（Lambda・API Gateway・WebSocket）
- CloudWatch Metrics で API 失敗率・レイテンシを可視化
- 外部 API（ElevenLabs）の呼び出し成功率・レスポンス時間を独自メトリクスで計測
- 基本的な単体テスト（Jest）・統合テスト（Lambda 統合テスト）

### NFR-07: AI 機能の失敗時挙動（フォールバック）

実サービス品質を見せる上で、AI 機能の失敗時挙動は必須要件として位置付ける。

| 失敗ケース | フォールバック | ユーザー通知 |
|---|---|---|
| クローンボイス生成失敗（ElevenLabs エラー） | 通常 TTS（Amazon Polly 標準音声）にフォールバックして対話継続 | 「クローンボイスを再生成できます」のリトライ導線を表示 |
| AI 応答が遅い（5 秒超） | ローディング文言・スピナーを表示 | 「考えています...」 |
| 録音品質が低い（無音・低音量・高ノイズ） | クライアント側で判定し再録音を案内 | 「もう少し大きな声で／静かな場所で再録音してください」 |
| STT 失敗（Transcribe エラー） | テキスト入力モードへの切り替えを案内 | 「音声認識ができませんでした。テキスト入力に切り替えますか？」 |
| LLM エラー（Bedrock スロットリング等） | エラーメッセージ＋リトライボタン | 「混み合っています。もう一度お試しください」 |
| WebSocket 切断 | 自動再接続を最大 3 回試行 | 切断バナー → 再接続成功時に解除 |
| 外部 API（ElevenLabs）レート制限 | キューに溜めて非同期処理。完了時にメール通知 | 「クローンボイスを準備中です。完了次第お知らせします」 |

- **優先度**: Must Have（実サービス品質をデモで見せるため）

## ユーザーシナリオ（主要）

### シナリオ 1: 企業研修での初回記録〜双方向対話（BtoB）

**前提**: MVP では BtoB 研修デモとして実施する。企業管理者アカウントや管理ダッシュボードは使わず、運営者が研修用テンプレート、参加リンク、デモ用リマインド導線を事前に準備する。

1. **研修シナリオの事前準備（MVP 運用）**
   - 運営者が企業研修用デフォルトフォーマットを選択
   - 研修参加者向けの参加リンク、またはデモアカウントを準備
   - 「2 年前のあなたが話しかけています」というデモ用リマインド導線を準備

2. **研修参加者のアカウント作成**
   - 従業員が参加リンクまたは通常登録フローからアクセス
   - 氏名・メールアドレス・パスワードを設定してアカウント作成完了
   - MVP では企業紐付けや一括招待は行わず、個人単位のコア体験として扱う

3. **Day 1 記録（入社初日）**
   - ログイン後、「Day 1 を記録しよう」の画面が表示される
   - ガイド付きフォーマットに沿ってテキストを入力（入社理由・やりたいこと・なりたい社会人像 等）
   - クローンボイス生成・第三者 API 送信への同意ダイアログを確認・同意
   - 録音画面で自分の声で 1〜2 分録音（直前のテキストは参考として表示）
   - 写真（任意）をアップロード
   - 「記録する」ボタンで保存
   - バックグラウンドでクローンボイス生成が開始される（完了時に通知）

4. **研修での再会導線（入社 2 年後を想定）**
   - MVP では運営者が共有したリンク、または簡易メール通知から対話セッションに誘導
   - 通知文言は「2 年前のあなたが話しかけています」
   - フェーズ 2 では BtoB 管理者が入社日を起点に自動リマインドを設定する

5. **クローンボイスとの双方向対話（研修導線経由）**
   - 通知内リンクまたは研修用リンクからアプリを開く
   - 「Day 1 の自分」との対話セッションが開始
   - 過去の自分の声（クローンボイス）が「入社を決めた理由」「3 年後の自分へのメッセージ」を語りかける
   - **ユーザーが返答する → 過去の自分が応答する → さらにユーザーが応える**、という双方向対話が進む
   - セッション終了後、振り返りメモ（自由記述）を保存できる

6. **任意タイミングでの対話**
   - リマインド通知を待たずに、ユーザーがいつでもホーム画面から「Day 1 の自分と話す」ボタンで対話セッションを開始できる
   - 仕事で行き詰まったとき・転職を考えたときなど、自発的に原点回帰できる

### シナリオ 2: ダイエット・健康管理（BtoC・将来拡張）

**前提**: BtoB 研修 MVP と同じコア体験を、個人ユーザー向けに横展開する。

1. ユーザーが Web アプリにアクセスし、メールアドレスでアカウント登録
2. ダイエット開始日に「Day 1」をダイエット用フォーマットで記録
   - 「なぜ痩せたいのか」「理想の自分の姿」「なりたい自分・なりたくない自分」「1 年後の自分へのメッセージ」
   - 現在の写真（任意）
   - クローンボイス用同意 → 自分の声で録音 → クローンボイス生成（バックグラウンド）
3. 毎週月曜日にリマインド通知を設定
4. 挫折しそうなとき・食欲に負けそうなときにホーム画面から「Day 1 の自分と話す」を選択
5. 過去の自分の声（クローンボイス）と双方向対話：今の自分が「どうしてもやめたい」と言うと、過去の自分が「なぜ始めたか」を踏まえて問いかけてくる
6. セッション終了後、振り返りメモを保存

### シナリオ 3: 大学受験・進路決定（教育機関・将来拡張）

**高校・塾での活用**:
1. 高校または塾が Day 1 と機関契約
2. 学生向けアカウントを配布（未成年利用時は保護者同意・外部 API 規約確認を前提）
3. 受験勉強開始時・志望校決定時に「Day 1」を記録（同意 → 音声収録 → クローンボイス生成）
4. 受験期間中、モチベーションが落ちたときに「Day 1 の自分と話す」
5. 過去の自分の声と双方向対話：今の自分の悩み（科目が伸びない、進路で迷う）に、当時の自分が記録した動機を踏まえて応える

**大学での活用**:
1. 大学が Day 1 と機関契約
2. 入学式・ガイダンス時に在学生全員にアカウントを配布
3. 入学時の「なぜこの大学・学部を選んだか」「4 年間で何を成し遂げたいか」を記録
4. 就活・卒論・スランプ時に原点回帰

### 技術検証ステータス

各技術の選定根拠と、ハッカソン MVP に向けた検証ステータスを明示する。

| 技術 | 用途 | 検証ステータス | 確認した観点 | 残課題 |
|---|---|---|---|---|
| Amazon Bedrock **Nova 2 Lite** | LLM 応答生成 | ✅ 確認済み（API 提供） / 🟡 要 PoC（応答速度・日本語品質） | 1M トークンコンテキスト、日本語対応、商用利用可（AWS 通常利用規約）。価格は Amazon Bedrock Pricing に準拠 | 日本語応答の自然さ、長文コンテキスト下での応答速度 |
| Amazon **Transcribe** | STT（音声→テキスト） | ✅ 確認済み（日本語ストリーミング・Tokyo リージョン対応） / 🟡 要 PoC（ノイズ環境精度・短い発話の認識率） | 多言語対応、リアルタイムストリーミング対応、商用利用可。価格は AWS Pricing に準拠 | 雑音環境での認識精度、フィラー除去 |
| **ElevenLabs Flash v2.5** | クローンボイス生成・TTS | ✅ 確認済み（日本語含む 32 言語、75ms レイテンシ、Voice Cloning 対応） / 🟡 要 PoC（日本語クローンボイス品質） | Instant Voice Cloning（30 秒〜2 分音声サンプル）、有料プランで商用利用可、ユーザー本人の声のみ登録可（同意必須） | 日本語クローンの自然さ、感情表現の再現度、レート制限 |
| **Amazon Bedrock Nova 2 Sonic** | speech-to-speech | ❌ 不採用 | 2025/12 リリース、低レイテンシ S2S | **クローンボイス機能なし（Day 1 の根幹を満たせず却下）**／日本語が公式サポート外 |
| **WebSocket**（API Gateway WebSocket API） | リアルタイム双方向対話 | 🟡 設計済み・実装未検証 | API Gateway WebSocket + Lambda 構成、コネクション管理 | 同時接続数のスケール、再接続ハンドリング |
| **Amazon Cognito** | 認証 | ✅ 確認済み（メール+SSO 対応） / 🟡 要 PoC（MVP の簡易登録・デモリンク） | User Pool + Identity Pool、Google ソーシャルログイン。BtoB 招待リンクのカスタムフローはフェーズ 2 | 招待トークン有効期限、企業ドメイン制限 |
| **AWS Amplify Hosting** | Next.js デプロイ | ✅ 確認済み（App Router 対応・Next.js 15 まで） / 🟡 要 PoC（SSR の Tokyo リージョン構成） | Lambda@Edge + CloudFront、CI/CD 内蔵、ブランチごとの環境分離 | SSR コールドスタート、画像最適化挙動 |
| **Amazon DynamoDB** | データ永続化 | ✅ 確認済み（フルマネージド・サーバーレス整合性） | オンデマンド課金、KMS 保存時暗号化、GSI による検索 | アクセスパターン設計（フェーズ 2 でホットキー対策） |
| **Amazon S3** | メディア保存 | ✅ 確認済み | SSE-S3 暗号化、Presigned URL、ライフサイクル | バケットポリシー、CORS |
| **Amazon SES** | メール通知 | ✅ 確認済み（Tokyo） / 🟡 要 PoC（送信ドメイン認証） | SPF / DKIM / DMARC、サンドボックス → 本番昇格 | 本番昇格申請、送信レピュテーション |
| **Amazon EventBridge Scheduler** | リマインドスケジュール | ✅ 確認済み（cron 式対応） | flexible time window、retry policy | MVP は手動・簡易導線、BtoB 一括自動配信はフェーズ 2 |

**凡例**: ✅ 確認済み / 🟡 要 PoC（ハッカソン期間中に検証） / ❌ 不採用

### Nova 2 Sonic を採用しなかった理由

Amazon Nova 2 Sonic は 2025 年 12 月にリリースされた speech-to-speech 一体型モデルで低レイテンシのリアルタイム会話 AI を実現する。しかし、Day 1 では採用しない：

1. **決定的理由：クローンボイス機能がない** — Nova 2 Sonic は内蔵の限定的な音声で応答するモデルであり、特定話者（本人）の音声クローンを差し込む API がない。Day 1 のコアバリューである「**過去の自分の声で応えてくれる双方向対話**」を実現できないため、本サービスの根幹を満たせない
2. **副次理由：日本語が公式サポート外** — 公式サポート言語は英語・スペイン語・ドイツ語・フランス語・イタリア語・ポルトガル語・ヒンディー語のみ
3. **採用構成**: Day 1 では「**Transcribe（STT）+ Nova 2 Lite（LLM）+ ElevenLabs Flash v2.5（クローンボイス TTS）**」の 3 段構成で、双方向対話とクローンボイスを両立する

### プラットフォーム

- **MVP**: Web アプリケーション（レスポンシブ対応）
- **将来**: スマートフォンアプリ（iOS / Android）、スマートデバイス連携

### クラウドインフラ

- **クラウドプロバイダー**: AWS
- **ストレージ**: Amazon S3
- **認証**: Amazon Cognito
- **AI / ML**: Amazon Bedrock Nova 2 Lite（LLM）+ Amazon Transcribe（STT）+ ElevenLabs Flash v2.5（クローンボイス TTS）

### アーキテクチャ方針

- フロントエンド：Next.js（App Router）/ AWS Amplify
- バックエンド：サーバーレス（AWS Lambda + API Gateway）
- AI 処理：Transcribe（STT）→ Nova 2 Lite（LLM）→ ElevenLabs Flash v2.5（TTS）の 3 段パイプライン
- クローンボイス生成はバックグラウンドジョブ（非同期処理）
